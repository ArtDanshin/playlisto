# Настройка деплоя на GitHub Pages

## Автоматический деплой

Проект настроен для автоматического деплоя на GitHub Pages при каждом push в ветки `main` или `master`, если изменяются файлы в папке `services/frontend/`.

## Настройка репозитория

### 1. Включение GitHub Pages

1. Перейдите в настройки репозитория: `Settings` → `Pages`
2. В разделе "Source" выберите "GitHub Actions"
3. Сохраните настройки

### 2. Настройка прав доступа

1. Перейдите в `Settings` → `Actions` → `General`
2. В разделе "Workflow permissions" выберите "Read and write permissions"
3. Включите "Allow GitHub Actions to create and approve pull requests"

## Структура деплоя

- **Workflow файл**: `.github/workflows/deploy-frontend.yml`
- **Сборка**: Используется Next.js статический экспорт (`next build` с `output: 'export'`)
- **Base path**: `/playlisto/` (настроен в `next.config.js`)
- **Output**: Статические файлы генерируются в папку `out/`
- **SSG**: Все страницы генерируются статически при сборке

## Локальная сборка для GitHub Pages

Для тестирования сборки локально:

```bash
cd services/frontend
rushx build
# Результат сборки будет в папке out/
```

## URL приложения

После настройки приложение будет доступно по адресу:
`https://[username].github.io/playlisto/`

где `[username]` - имя пользователя GitHub или организации.

## Troubleshooting

### Проблема с путями

Если приложение не загружается корректно, проверьте:
1. Правильность настройки `basePath` в `next.config.js`
2. Что все ссылки в приложении используют относительные пути
3. Что `output: 'export'` настроен в `next.config.js`

### Проблема с правами доступа

Если деплой не запускается:
1. Убедитесь, что в настройках репозитория включены GitHub Actions
2. Проверьте права доступа в `Settings` → `Actions` → `General`
3. Убедитесь, что workflow файл находится в правильной ветке

### Проблема с роутингом

Next.js с SSG решает проблему роутинга на GitHub Pages автоматически:
- Все страницы генерируются статически при сборке
- Динамические маршруты (например, `/playlist/[id]`) работают через клиентскую навигацию
- При прямом переходе по URL необходимо настроить 404 редирект на GitHub Pages (Next.js создает 404.html автоматически)

**Важно**: `basePath` в `next.config.js` должен быть `/playlisto` для production.

## Оптимизация

Next.js автоматически оптимизирует бандлы:
- Автоматическое code splitting по маршрутам
- Tree shaking неиспользуемого кода
- Оптимизация React компонентов
- Минификация и сжатие статических файлов
